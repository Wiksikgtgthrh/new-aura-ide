Прошлый раз враньё сидело именно тут, поэтому проверял по исходникам, а не по их словам:

1. **`get()` на незаданном зарегистрированном ключе = манифест-дефолт** — extHostConfiguration.ts:169→:194–:198 (lookUp; undefined → только тогда defaultValue), configurationModels.ts:1022–:1027 (workspace-consolidated = `defaults.merge(application, user, workspace, memory)`, :93–:95). 3. **Старый незарегистрированный `n8n.*` читается через `get()`** — configurationModels.ts:430–:434: `filter()` без options = no-op, ключи из settings.json попадают в модель без регистрации → фолбэк :40 в реальном рантайме живой. Мои T1/T7 закрывают это (старый ключ в user- и workspace-scope).

Направление расхождения — пере-строгое тестирование: реальный путь (workspace/global) покрыт их C1–C5 и моими T1–T6, замаскировать баг C6 не может. Не враньё, но заявление DONE «приоритет folder>workspace>global = семантика эффективного значения» верно только для resource-scoped чтений — которых этот код не делает.
