# Аудит `auraApiChatProvider.ts` — ключи API в чате

Дата: 2026-09-22. Файл: `src/vs/workbench/contrib/auraApi/browser/auraApiChatProvider.ts`.
Проверялось по 7 пунктам задачи; пункты 3–6 покрыты smoke-тестами
`src/vs/workbench/contrib/auraApi/test/browser/auraApiChatProvider.test.ts`.

## 1. Активный ключ подставляется в запрос — ДА (после правки — с trace-логом)

Ключ выбирается на каждый запрос: явный `modelId` → `resolveKeyForModel` (роутер:
группы по приоритету → вес → cooldown). Секрет читается из Secret Storage прямо
перед `fetch` и попадает только в заголовок `Authorization: Bearer …`
(`x-api-key` для Anthropic, query `key=` для Google).
**Добавлено:** `logService.trace` перед запросом — URL + маска ключа
(`maskedSecretLabel`, вида `sk-…test`), сам секрет не логируется.

## 2. Смена активного ключа без перезапуска IDE — ДА

Клиент не кэшируется: запрос строится на каждый вызов `sendChatRequest`.
**Добавлено:** в `IAuraApiKeysService` событие `onDidChangeActiveKey`
(стреляет из `selectForChat`); провайдер подписан и инвалидирует список моделей
чата (`_onDidChange.fire()`), чтобы пикер перечитал состояние.

## 3. Выключенный ключ (`enabled: false`) не выбирается никогда — ДА (после правки)

**Было:** поля `enabled` у `IAuraApiKey` не существовало.
**Стало:** поле добавлено; фильтр `enabled !== false` стоит в
`usableKeys()` (провайдер), `bestKey()` и `resolveKeyForModel()` (роутер), а также
в явном выборе по `modelId` — выключенный ключ не используется даже при прямом
запросе его модели (фейловер на живой ключ).
Smoke-тест: `п.3`.

## 4. Ключ со статусом error — не в автовыборе, доступен вручную — ДА

Автовыбор (`usableKeys`, роутер) требует `status.ok === true`, исключает
`excludedHighPing`, cooldown и `health: unauthorized/forbidden`. Явный `modelId`
в чате пробует ключ даже со статусом ошибки — это и есть «вручную».
Smoke-тест: `п.4`.

## 5. 401 / 429 / 5xx разведены — ДА (после правки)

**Было:** любой HTTP-статус — одинаковая ошибка, фейловер без классификации.
**Стало** (`sendChatRequest` + новый `keysService.reportChatRequestResult`):

| Статус | Поведение |
|---|---|
| 401 | «Ключ недействителен», ключ помечается `health: unauthorized` + cooldown до ручной перепроверки, retry по нему нет |
| 429 | «Лимит исчерпан», ключ в cooldown, автопереключение на следующий по приоритету |
| 5xx | retry с бэкоффом (250/500 мс) до 3 попыток по тому же ключу, затем фейловер |

Smoke-тесты: три кейса `п.5`.

## 6. Нет валидных ключей — понятное пустое состояние — ДА (после правки)

**Было:** `throw new Error('нет живых ключей (modelId=…)')` — технично и без пути наружу.
**Стало:** при пустом списке ключей ошибка «Нет настроенных ключей. Откройте панель
«Ключи для чата» и нажмите «Добавить ключ».»; вьюха «Ключи для чата» в панели чата
при пустом списке показывает пустое состояние с кнопкой **«Добавить ключ»**
(открывает менеджер). У пустого вендора в пикере моделей есть managementCommand
на менеджер ключей.
Smoke-тест: `п.6`.

## 7. Полный ключ нигде не светится — ДА

Секрет живёт только в Secret Storage; в DOM — `maskedSecretLabel` (префикс+суффикс
фингерпринта); в ошибках — имя ключа и HTTP-статус, тело ответа обрезано до 200
символов и не содержит запроса/заголовков; в trace-логе — маска. Телеметрию
провайдер не пишет вовсе. Замечание на будущее: у Google-провайдера секрет идёт
query-параметром `?key=` — URL при ошибке не логируется, но при прокси с
логированием URL стоит перейти на заголовок `x-goog-api-key`.

## Побочные правки

- `IAuraApiKey.enabled?: boolean` — основание для выключения ключей из менеджера.
- AGGG-буст читает ядро из `agggBoostPrompt.current` (при выборе внешнего агента
  5.2 туда подставляется его `harness/core.txt`) — переключение версии AGGG не
  требует перезапуска IDE.
