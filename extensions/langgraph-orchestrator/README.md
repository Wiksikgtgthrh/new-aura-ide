# LangGraph Оркестратор

Встроенное расширение Aura IDE: мультиагентный оркестратор на LangGraph.js
с тир-маршрутизацией API-ключей (supervisor/воркеры на high/mid/low тирах).

## Что умеет

- **Команда агентов**: supervisor-планировщик строит DAG-план раунда
  (`nodes[{id, goal, deps[], tier, kind, files_hint[]}]`, строгая JSON-схема +
  один ретрай при невалидном ответе); узел `router` делает fan-out готовых
  подзадач через `Send` по лимиту параллелизма, поэтому ни одна подзадача плана
  не теряется, даже если её больше, чем воркеров. Независимые подзадачи летят
  параллельно, зависимые ждут закрытия deps. Тип работы (`kind`) задаёт агента:
  `code→coder`, `test→tester`, `review→reviewer`, `security→security-auditor`,
  а `search`/`boilerplate` принудительно уходят на `low`.
- **Reducer и результаты**: вывод воркера сжимается узлом `reducer` в
  `results[node] = {status, summary (≤5 строк), diff_stat, commit, tokens, cost}`;
  сырые ответы в state не остаются, как и логи терминала или содержимое файлов —
  только резюме и ссылки. Расход (токены) копится в `budget`, ошибки — в `errors`.
  Узел `join` после каждой пачки решает: очередь исчерпана — назад к
  планировщику (merge/finish), иначе снова `router`.
- **Тиры ключей**: каждому ключу из банка плагина API Keys (и командным `Team · …`)
  назначается тир — high/mid/low. До первого выбора тир выводится эвристикой по
  названию модели (mini/flash/haiku → low, opus/pro/large → high), затем виден
  в панели и меняется вручную; выбор хранится в globalState и переживает
  перезапуск IDE. Роли привязаны к тирам: supervisor и coder работают на high,
  tester на low, auditor/reviewer на mid.
- **Ключи и статусы**: живость, пинг и cooldown берутся из ядра API Keys
  (`apiKeys.exportStatuses`), перепроверка — `apiKeys.checkKeys`; строки командного
  банка видны рядом как сведения. В таблице ключей есть фильтр по источнику
  (личные/командные), «Проверить все» перезапрашивает пинг и у ядра, и у
  командного банка. Кандидаты одного тира раздаются по загрузке (сначала
  свободные, потом быстрые), лимит агентов на ключ —
  `langgraphOrchestrator.maxAgentsPerKey`.
- **Тир-хинты подзадач**: supervisor помечает каждую подзадачу тиром —
  бойлерплейт и поиск по файлам уходят на дешёвый low, тяжёлый рефакторинг —
  на high, независимо от роли агента.
- **Самолечение (evaluator-optimizer)**: после провала подзадачи verify-нода
  может прогнать реальную проверку (`langgraphOrchestrator.verifyCommand`,
  например `npm test`) и отправляет воркеру на ретрай текст фактической ошибки
  — без участия супервизора, до `langgraphOrchestrator.maxVerifyRetries` раз.
- **Умный роутинг и фейловер**: ключ умер (401/403) — выводится из строя;
  429 — cooldown 60 с; сетевая ошибка — 30 с. Запрос перебирает кандидатов
  внутри тира, затем тиры **только выше** (low → mid → high): дешёвый тир —
  осознанный выбор роли, а не запасной выход. Один умерший ключ не роняет
  запуск — прокси переключается на следующего кандидата. Узел графа,
  провалившийся N раз, эскалируется на тир выше
  (`langgraphOrchestrator.escalationThreshold`).
- **Подтверждения**: запись файлов и терминал — через аппрув в карточке агента
  в панели (или модалку). Политика: `auto-readonly | confirm-writes | confirm-all`.
- **Изоляция и предохранители (Этап 4)**: каждый пишущий воркер работает в своём
  git worktree (`.aura/worktrees/<run>/<node>`, ветка `aura/<run>/nodes/<node>`) — основное
  дерево воркеры не трогают. После правки узел гоняет проверки проекта
  (`langgraphOrchestrator.checks`) внутри своего дерева и, при падении, получает
  только первые 40 строк ошибок и имена упавших тестов; жёсткий лимит
  `maxFixIterations` (3), после — статус `needs_human` и карточка подтверждения.
  Ветки узлов по очереди мёржатся супервизором в `aura/<run>/run`; конфликт — interrupt
  со списком файлов, без авто-резолва моделью. Опасные действия (`git push`,
  удаление, сеть, запись в `.env`/ключи) останавливают граф до подтверждения.
  В конце — единый патч с кнопками **Применить / Отклонить / Открыть diff**
  (multi-diff); отклонение удаляет worktree и ветки, не оставляя следов.
- **Бюджет, трейсинг, кэш (Этап 5)**: лимиты токенов и $ на запуск и на каждый
  узел (`langgraphOrchestrator.budget`, 0 — без лимита), цены моделей по тирам
  с пер-модельными переопределениями (неизвестная — high). Прокси считает
  usage с каждого ответа; перерасход узла → `needs_human`, перерасход запуска →
  пауза всего графа и карточка подтверждения. В панели есть блок **Бюджет**:
  прогресс к лимитам запуска, расход по моделям (токены/$, вызовы),
  командные траты по людям и кнопка **Очистить кэш**. Лимиты и цены можно
  менять прямо из панели (без правки settings.json) — изменения применятся
  к следующему запуску; есть профили бюджета (встроенные `economy`/`normal`/`max`
  и свои именованные наборы) с переключением одним кликом. Командные цифры —
  когда Aura Team отдаёт `getUsage()`.
  Вкладка **Trace** показывает водопад спанов нод и LLM-вызовов (токены, $,
  длительность, ретраи) и топы по времени и по деньгам; спаны опционально
  пишутся JSONL в `.aura/orchestrator/traces` и могут экспортироваться на OTLP
  endpoint (в спанах нет промптов и ключей). Read-only инструменты
  (`fs.readFile`, `fs.listFiles`, `fs.search`/`grep`, `symbols.list`) кэшируются
  в SQLite (globalStorage) по ключу `(tool, args, commit_sha, dirty_hash)` —
  повторный вызов в том же коммите не трогает файлы.
- **Живучесть**: сайдкар — отдельный процесс и прогревается при активации;
  в шапке видно, готов ли он (с причиной ошибки и кнопкой запуска). Состояние
  графа снапшотится после каждого узла в `.aura/orchestrator/checkpoints/latest.json` —
  повторный запуск той же задачи продолжает с чекпоинта. Полная история
  чекпоинтов (машина времени: history/rewind/patchState) хранится рядом
  в `graph-store.json` и переживает рестарт сайдкара и IDE.
- **Панель**: пять вкладок — **Запуск / Доска / Модели / Трасса / Журнал**
  (`run/board/models/trace/log` в коде и командах палитры). Шапка:
  чип сайдкара (ready/starting/error), бюджетный чип «токены · $» с полоской
  расхода и иконки паузы/продолжения/остановки. Вкладка **Run** — поле задачи
  с переключателем «Своя задача / С доски», справочная строка «Планнер /
  Макс. параллель», план как список-DAG (отступ по зависимостям, иконка
  статуса, тир-бейдж LOW/MID/HIGH, модель, токены, время); клик по ноде
  открывает её цель, итог и `diff --stat` с кнопками **Открыть diff** и
  **Перезапустить**; сверху — блок «Ждёт тебя» (подтверждение рискованной
  подзадачи с заметкой), внизу — таймлайн чекпоинтов (откат/правка состояния).
  Пустое состояние подсказывает примеры задач. **Models** — таблица моделей двух
  источников с сегмент-контролом тира (правка на месте), статусом, пингом и
  «Used today» (вызовы и токены по `budget.perModel`); там же сворачиваемый блок
  бюджета (лимиты, цены, профили, командные траты, очистка кэша). **Доска** —
  компактный канбан команды: карточки с кнопкой «Отдать агентам» и форма «своя
  задача» сверху (поле, колонка, «Добавить задачу»; Enter в поле тоже создаёт).
  **Трасса** — водопад
  спанов и топы по времени/деньгам. **Log** — моноширинный журнал с фильтром по
  уровню и ноде и кнопкой закрепления автоскролла. Сообщения webview↔extension —
  типизированные `{type, payload}`, состояние UI собирается одним reducer'ом,
  а строки из снапшота вставляются только через `textContent`. Язык панели —
  `langgraphOrchestrator.uiLanguage` (`ru` по умолчанию, `en`, `auto` — как в IDE),
  хост отдаёт webview уже разрешённое значение; на том же языке supervisor
  просит инструкции, из которых берутся заметки на карточках. Вкладка панели
  подписана «Оркестратор».
- **Русский интерфейс везде.** Строки манифеста (заголовки команд в палитре,
  описания настроек, имя расширения и вью) впечатаны в `package.json` по-русски,
  а не взяты через `package.nls` — тот выбирается по локали IDE, и при английской
  IDE палитра с настройками оставались английскими. Файлы `package.nls*.json`
  сохранены как словарь перевода (ru — эталон); тест сверяет с ними манифест.
- **Мост с Aura Team**: если плагин Team установлен, в панели появляется вкладка
  «Доска» с задачами команды, а на карточке задачи на доске Team — кнопка «Отдать
  агентам» (команда `orchestrator.runTeamTask`). Свою задачу создаёт форма на
  вкладке: `team.createTask` → `bridge.createTask` → публичный `createTask` Team
  (тот же `POST /v1/teams/:id/tasks`), затем доска перечитывается. Старт переводит задачу в `doing`
  и пишет заметку в описании; готовый патч — в `review`, ошибка — остаётся
  в работе с коротким резюме. Повторный клик продолжает тот же поток графа
  (taskId → threadId в globalState). Без плагина вкладка и кнопка не появляются,
  всё остальное работает как раньше.

## Архитектура

```
extension host (этот пакет)              sidecar (dist/sidecar.cjs)
┌───────────────────────────────┐ stdio ┌──────────────────────────┐
│ панель (Custom Editor)        │ JSON- │ LangGraph.js StateGraph  │
│ KeyRegistry (тиры/статусы)    │ RPC   │ planner → router →       │
│ ModelCatalog · TierStore      │       │ worker → reducer →       │
│                               │       │ verify → join → …        │
│ LocalLlmProxy ←── HTTP ───────┼───────┤ LLM: тир вместо модели   │
│   └→ RouterProxy → vscode.lm  │ loop- │ tools — RPC сюда         │
│ ToolExecutor (fs/term/diag) ──┼──RPC──┤                          │
└───────────────────────────────┘ back └──────────────────────────┘
                            ▼
              ядро: AuraApiChatProvider
       (секреты, cooldown, фейловер, tool calling)
```

Секреты ключей сайдкар не видит. LLM-вызов идёт HTTP-запросом на локальный
прокси расширения (`POST /v1/chat/completions`): в теле — **тир**, а не модель.
Прокси выбирает живой ключ тира, переключается между кандидатами и поднимается
на тир выше, если дешёвый пуст. Сайдкар получает только `AURA_PROXY_URL` и
случайный `AURA_RUN_TOKEN` через окружение процесса; сам прокси слушает только
`127.0.0.1` и не пишет токены и ключи в лог. Сам вызов исполняется через
`vscode.lm` (vendor `apiKeys`, идентификатор модели — `apiKeys/<id ключа>`).
RPC-путь `chat.complete` остаётся фолбэком для mock-режима и тестов.

## Команды

- `LangGraph Оркестратор: Открыть оркестратор` (`auraOrchestrator.open`)
- `…: Запустить задачу` / `Пауза` / `Продолжить` / `Отменить задачу`
- `…: вкладка Run / Board / Models / Trace / Log` — открывают панель и сразу
  переключают её на нужную вкладку (`auraOrchestrator.tab.*`)
- Горячие клавиши в фокусе панели: **F6** — пауза, **F7** — продолжить,
  **F8** — остановить (`when: activeCustomEditorId == 'auraOrchestrator.panel'`).
  Те же клавиши дополнительно обрабатывает сам webview.

## Настройки

| Ключ | Назначение | Дефолт |
|---|---|---|
| `langgraphOrchestrator.tiers.rules` | Правила назначения тиров (match/priorityFrom/priorityTo → tier) | `[]` |
| `langgraphOrchestrator.tierOverrides` | Жёсткий тир по id ключа из настроек; выбор в панели хранится отдельно в globalState и переживает рестарт | `{}` |
| `langgraphOrchestrator.approvals` | Политика аппрувов инструментов | `confirm-writes` |
| `langgraphOrchestrator.maxParallelWorkers` | Лимит параллельных воркеров (размер пачки из очереди) | `3` |
| `langgraphOrchestrator.maxAgentsPerKey` | Сколько агентов одновременно на один ключ (0 — без предела) | `0` |
| `langgraphOrchestrator.uiLanguage` | Язык панели и заметок агентов (`ru`/`en`/`auto` — как в IDE) | `ru` |
| `langgraphOrchestrator.escalationThreshold` | Провалов до эскалации тира | `2` |
| `langgraphOrchestrator.maxVerifyRetries` | Ретраев провалившейся подзадачи до сдачи | `2` |
| `langgraphOrchestrator.verifyCommand` | Команда проверки для verify-ноды (пусто — только эвристика по тексту результата) | `` |
| `langgraphOrchestrator.teamAutoGrab` | Автозабор задач доски Team из `todo` с меткой `[agent]` | `false` |
| `langgraphOrchestrator.teamAutoGrabLimit` | Глубина очереди автозабора (граф идёт по одной) | `2` |
| `langgraphOrchestrator.terminalAllowlist` | Префиксы команд без аппрува | npm test и т.п. |
| `langgraphOrchestrator.gitPath` | Путь к git-бинарнику (worktree/merge) | `git` |
| `langgraphOrchestrator.checks` | Команды проверок для самолечения (lint/typecheck/test) | `[]` → npm lint/tsc/test |
| `langgraphOrchestrator.maxFixIterations` | Лимит итераций правка → проверка в воркере | `3` |
| `langgraphOrchestrator.budget` | `runTokens`/`runCost`/`nodeTokens`/`nodeCost` (0 — без лимита), `prices` по тирам, `modelPrices` | лимиты `0`, цены по тирам |
| `langgraphOrchestrator.trace` | `enabled`, `file` (JSONL в `.aura/orchestrator/traces`), `maxSpans`, `otlpEndpoint` | `enabled`, буфер в памяти |

## Сборка и тесты

```bash
npm install                      # dev-зависимости расширения
cd sidecar && npm install        # зависимость сайдкара: @langchain/langgraph
cd ..
node build/compile-sidecar.mjs   # бандл сайдкара → dist/sidecar.cjs
npm run gulp -- compile-extension:langgraph-orchestrator   # из корня репо
node test/run-all.mjs            # юнит-тесты
node test/smoke-sidecar.mjs      # дымовой прогон графа (mock-LLM)
node test/panel-preview.mjs      # стенд панели: out/panel-preview.html с фейковым состоянием
```

Тесты графа идут без расхода ключей: `AURA_ORM_MOCK_LLM=1` включает
детерминированные ответы LLM в сайдкаре.

## Ограничения

- Командные ключи участвуют через прокси-мост (`Team · …`): сервер сам
  выбирает конкретный ключ по приоритету — per-key гранулярности нет. Ключи
  командного банка без локального прокси в панели — только сведения.
- Отменить можно и одну подзадачу, а вот повторить отдельную нельзя: план
  задаёт supervisor, и повторный прогон — это новый запуск задачи.
- Tool calling у Google-ключей в ядре ограничен (tools схлопываются в текст):
  воркеры на таких ключах работают в деградированном режиме.
- Чекпоинт гранулярен до узла графа (не внутри агентного цикла): после
  `interrupt` воркер переигрывается целиком — уже сделанные правки в его worktree
  остаются, но агентный цикл начинается заново.
- Worktree живут внутри репозитория (`.aura/worktrees`) и игнорируются git.
  Merge-конфликты разрешает человек: модель их не резолвит по умолчанию.
- PostgresSaver не подключён: персистентность — JSON-файл в рабочей папке,
  чего достаточно для одного пользователя IDE. `AsyncSqliteSaver` в JS-пакете
  `langgraph-checkpoint-*` не поставляется (доступен только `MemorySaver`),
  поэтому используется `FileSaver` с той же персистентностью.
- Стоимость в `results.cost` пока 0: прайсинга моделей у нас нет, копятся
  только токены (`budget.tokens`). `diff_stat`/`commit` заполняются, только
  если доступен git и разрешён `terminal.run`.
