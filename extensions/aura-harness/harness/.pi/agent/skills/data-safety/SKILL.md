# Data Safety

## Перед изменением данных

1. Определи окружение: local / staging / prod. Не уверен, считай prod.
2. Backup или снапшот: `pg_dump -Fc`, снапшот провайдера, копия файла. Запиши путь в `note`.
3. Сначала SELECT с тем же WHERE: сколько строк затронет. Число в запрос approval.
4. Изменение в транзакции, где это возможно: `BEGIN; ... ; SELECT проверка; COMMIT;`.

## Миграции

- Только через инструмент проекта (prisma, drizzle-kit, knex, alembic), без ручного DDL в проде.
- Сначала на локальной базе или ветке базы (Neon branch, staging).
- Деструктивные шаги (DROP, удаление колонки, смена типа) разбивай: expand, переключение кода, contract отдельным релизом.
- План отката: down-миграция или restore из backup с оценкой времени.
- Команды migrate/push в политике `ask`. Вместе с задачей risk `destructive`.

## Запрещено

- `UPDATE`/`DELETE` без `WHERE` и без предварительного подсчёта.
- `TRUNCATE`/`DROP` без backup и approval.
- Копировать прод-данные на локальную машину без маскирования.
- Класть дампы, CSV с персональными данными и `.env` в git или в чат.

## Персональные данные и секреты

- В логах и отчётах маскируй email, телефоны, токены: `a***@x.com`.
- Секреты только из окружения. Нашёл секрет в коде: `policy.mjs scan`, удалить, ротировать ключ, сказать человеку.
