# Media Assets

Модель сама картинки не рисует. Генерация работает только если в окружении есть
инструмент: MCP-сервер (fal, replicate, openai-image, comfyui и т.п.), CLI или API-ключ
в env. Нет инструмента — так и скажи, не выдумывай файл.

## Промпт слоями (вместо «сделай красивую картинку»)

Описывай кадр шестью слоями, в этом порядке:
1. объект и композиция (что и как расположено, где пустое место);
2. ракурс и камера (wide/close-up, side lighting, 35mm);
3. материалы и физические свойства (worn wood, matte skin, glass);
4. свет, фон и палитра (точные hex фона для стыковки — см. deco-assets);
5. настроение (calm premium, honest rustic);
6. ограничения интеграции (no text, no logo, clean negative space left).

После генерации реши отдельно: что остаётся картинкой, что — CSS-анимацией,
что — 3D-сценой, что — интерактивным компонентом. Не пихай всё в один ассет.

## Встроенная генерация (основной путь)

На этой машине картинки рисует встроенная модель шлюза ZCode. Зови инструмент:

```bash
node ~/.agent-harness/tools/imagegen.mjs <out.png> "<промпт>" [size] [--ref <img>]
```

- Модель `gpt/gpt-image-2.5`; размеры `1024x1024`, `1536x1024`, `1024x1536`, `auto`.
- Ключ инструмент берёт сам из `~/.zcode/v2/provider_config.json` — в код, логи и
  репозиторий его не тащить и руками не искать.
- `--ref <img>` — правка присланной картинки (инпейнт, вариант кадра).
- Генерация идёт через `/v1/responses` с инструментом `image_generation`;
  **не** `/v1/images/generations` — шлюз отвечает на него `400 invalid_request_error`.
- Шлюз под нагрузкой отдаёт `503`/`429` — инструмент сам повторяет с паузой до
  ~5 минут. Это норма: ждём, а не подсовываем заглушку.
- Готовую фотографию пережми в WebP (`quality 84`, ширина ≤1200): PNG на 1536×1024
  весит ~3 МБ и убивает LCP.

## Резервный шлюз (codex.sale)

Если у сэра есть ключ и он просит именно его — codex.sale ([OI]-совместимый
`POST https://codex.sale/v1/images/generations`, модель `gpt-image-2.5-sunburst`,
ответ b64_json).

Ключи (секреты, в логи и репозиторий не писать):
- основной — `~/.secrets/codex-img-key`
- запасной (если файл существует) — `~/.secrets/codex-img-key-2`

Фолбэк: основной отвечает 401/402/403/429 или «insufficient balance/quota» →
повтори с запасным (если есть) и скажи пользователю, что переключился.
Все мертвы → verdict `unavailable`, попроси новый ключ. Env `OPENAI_API_KEY` для [OI] на
этой машине дохлый — на него не полагайся.

## Шаг 0. Обнаружение

0. Сначала встроенная генерация: `node ~/.agent-harness/tools/imagegen.mjs --help`
   или просто вызови её. Она есть на этой машине всегда, пока подключён провайдер
   ZCode, — и это путь по умолчанию; MCP и чужие ключи ниже нужны только если
   встроенная ответила отказом.
1. Посмотри список доступных MCP-инструментов: ищи `generate_image`, `text_to_image`,
   `image`, `video`, `fal`, `replicate`.
2. Нет MCP — проверь env по именам (не значениям): `FAL_KEY`, `REPLICATE_API_TOKEN`,
   `OPENAI_API_KEY`, `AI_GATEWAY_API_KEY`, `GEMINI_API_KEY`.
3. Ничего нет → verdict `unavailable`, предложи пользователю подключить один провайдер.
   Готовые записи `fal` (https://mcp.fal.ai/mcp, ключ `FAL_KEY`) и `replicate`
   (`npx -y replicate-mcp@latest`, ключ `REPLICATE_API_TOKEN`) лежат выключенными в
   `opencode/opencode*.jsonc.example` — включить одну и проверить `opencode mcp list`.
   Для ZCode: `zcode/mcp.example.json` → Settings > MCP Servers или
   `~/.zcode/cli/config.json` (ключ `mcp.servers`); проверить статус сервера в Settings.
   Не ставь плейсхолдер молча.

## Шаг 1. Бриф из design-map

- Возьми палитру, настроение и визуальный приём из `.agent-state/design-map.md`.
- Промпт = субъект + композиция + свет + палитра (hex из токенов) + стиль + «no text»,
  если текст будет поверх в вёрстке. Текст в картинке модели до сих пор пишут криво.
- Одна серия = один стилевой префикс промпта, иначе ассеты выглядят из разных сайтов.

### Стиль ассета под тип интерфейса

- **Плотный data-UI (терминалы, дашборды, админки): НЕЛЬЗЯ фотореалистичные
  рендеры** (3D-сцены с «мокрым полом», стульями, мониторами) — они спорят
  с интерфейсом и выглядят как стоковая реклама. Только плоская/абстрактная
  векторная графика: линии, геометрия, иконоподобные композиции в палитре
  токенов, минимум градиентных «бликов».
- **Маркетинг/лендинг**: фотореализм и 3D уместны в hero, но тоже в палитре
  токенов и одним стилем на всю серию.
- Ассет внутри панели/карточки должен быть тише интерфейса: приглушённый,
  небольшой, без собственной «сцены» с фоном — иначе панель превращается
  в рамку для картинки.

## Шаг 2. Генерация

- Размер под место в layout: hero 16:9 / 21:9, карточки 4:3 или 1:1, OG 1200x630.
- Генерируй 2–4 варианта, выбирай глазами (открой файлы), а не первый попавшийся.
- Видео: короткий луп 3–6 с, без звука, `muted autoplay loop playsinline`, плюс постер-кадр.
  Видео — тяжёлый ассет: только если оно реально несёт смысл (демо продукта), не фон ради фона.

## Шаг 3. Встраивание

- Сохраняй в `public/` проекта (или в принятый в проекте каталог), имена по смыслу:
  `hero-dashboard.webp`, не `image1.png`.
- Конвертируй в WebP/AVIF, задавай `width`/`height` (CLS), `alt` по смыслу, decorative → `alt=""`.
- Next.js: `next/image` с `sizes`; LCP-картинке — `priority`. Видео — `preload="none"` ниже фолда.
- Учитывай `prefers-reduced-motion`: видео/анимацию останавливай или заменяй постером.

## Шаг 4. Проверка

- Скриншот страницы в светлой и тёмной теме: ассет не спорит с токенами и контрастом.
- Gate `perf`: картинка не должна ронять LCP. Тяжело — уменьшай, а не оправдывайся.
- В отчёте: какой провайдер/модель, сколько вариантов, что выбрано и почему.
