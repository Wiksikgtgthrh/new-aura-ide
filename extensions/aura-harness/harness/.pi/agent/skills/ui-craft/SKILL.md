# UI Craft

Ты не собираешь «набор карточек». Ты проектируешь интерфейс с характером.

## Главный цикл

0. Прочитай `.agent-state/design-map.md` (нет — `node ~/.agent-harness/tools/design-map.mjs`).
   Есть система — работаешь в ней. Шаги 2–3 ниже только для нового проекта или явного редизайна.
   Инженерные правила (RSC, формы, состояния) — скилл `frontend-stack`.
1. Определи задачу страницы: кто смотрит, что должен понять и какое действие сделать.
2. Если стиль не задан — собери 2–3 визуальных направления через поиск референсов.
   Не копируй сайт целиком: вытащи композицию, ритм, типографику и поведение.
   **Сначала загляни в готовый корпус:** `~/.zcode/skills/design-taste-frontend/references/`
   (8 живых сайтов, desktop + mobile, разбор «что именно дорого» в `INDEX.md`).
   Открой 2–3 снимка нужной категории и назови вслух механизм, который берёшь
   (разрыв масштаба, пустота, студийный свет, стекло поверх фото, обрез краем,
   одно свечение). Копируем механизм, не айдентику.
3. Выбери одно направление и зафиксируй:
   - один главный цвет;
   - 2–3 нейтральных цвета;
   - максимум 1–2 акцента;
   - максимум 2 семейства шрифтов;
   - один запоминающийся визуальный приём.
4. Сначала собери скелет страницы и мобильную версию, затем детали.
5. После реализации открой реальный браузер и проверь desktop + mobile скриншотами.
   Исправляй то, что видно, а не то, что «должно работать».

## Визуальные правила

- Не используй дефолтный AI-стиль: фиолетовые градиенты, случайные glow-blob,
  одинаковые rounded cards и декоративные цифры без смысла.
- Не смешивай больше 3–5 цветов. Цвета должны быть токенами, а не россыпью
  `bg-white`, `text-black` и случайных hex по JSX.
- Для основного layout сначала используй flex, grid — только для настоящих 2D-сеток.
- Делай иерархию через размер, вес, контраст и отступы, а не через десять эффектов.
- Каждый декоративный элемент должен помогать бренду, навигации или фокусу.
  Если не помогает — убери.
- Изображения генерируются ВСЕГДА, это не опция. Любой сайт/лендинг: до начала
  вёрстки загрузи `media-assets` и сгенерируй нужные кадры (hero, продукты,
  текстуры, декор — по списку секций). Placeholder, серые прямоугольники,
  «временные» картинки и внешние стоки запрещены. Нет ни одного сгенерированного
  ассета → результат `unverified`, верстать не начинай. Исключение — одно:
  пользователь ЯВНО попросил без картинок/с заглушками. Правило про создание страниц/сайтов: точечная правка стилей/текста без новых изображений генерации не требует («доработай X» = только X).
  Для иконок предпочитай одну библиотеку и одинаковый размер.
- Состояния обязательны: hover, focus-visible, disabled, loading, empty, error.
- Семантическая разметка, alt-тексты, клавиатура и контраст — часть дизайна.

## Фон-герой: живой океан, фото, видео

Когда фон — настоящее зрелище (three.js-океан, видео, фото), интерфейс обязан
его не портить. Это самая частая ошибка: «чтобы читалось, затемню».

- **Никаких тёмных наложений.** Виньетки, `linear-gradient(rgba(4,20,26,.8), …)`
  поверх сцены, затемняющие «плашки под контраст» — всё это убивает то, ради чего
  фон делался, и наводит тоску. Читаемость дают `text-shadow` и светлые панели,
  а не затемнение.
- **Панели светлые.** Карточки, формы, тосты, подвал — `rgba(252,248,240,.94)`
  с тёмным текстом (`#06242c`), мягкой тенью и лёгким `backdrop-filter`. Такой
  блок лежит поверх океана как бумага и не забирает у него контраст.
- **Навигация при скролле — светлое стекло**, а не тёмная полоса.
- **Тон яркий.** Палитра — солнечная: тёплый песок + золото + бирюза. Депрессивные
  тёмно-серые темы на живом фоне не ставим.
- **Проверь, где окажется текст** по композиции: под ним должен быть плотный
  участок сцены (вода, тень), а не самое светлое небо.
- **CSS — в `<head>` линком.** `import './styles.css'` из JS даёт «голый HTML»
  на первом кадре и при каждом обновлении: браузер ждёт модуль. Это не мелочь,
  пользователь видит скелет страницы.

## Микровзаимодействия (стандарт, не украшение)

Интерфейс без отклика ощущается мёртвым. Минимум, который должен быть всегда:

- **Кнопки**: hover (яркость/фон 120–180мс), active (scale 0.97–0.98 или
  сдвиг на 1px — «нажатие»), transition на всё интерактивное. Кнопка без
  active-состояния — кнопка из 2010 года.
- **Кнопки должны двигаться сами.** Статичной заливки мало: рабочий минимум —
  `translateY(-2…-3px)` + рост тени на hover, бегущий блик (градиент, проезжающий
  через кнопку по `::before`), сжатие на `:active`. У текстовых кнопок — линия,
  растущая слева (`scaleX` с `transform-origin: left`). Всё на 0.35–0.55 с
  `cubic-bezier(.16,1,.3,1)`; проверять в браузере, а не «на глаз в коде».
- **Переключатели и табы**: выбор движется (sliding indicator, underline со
  смещением), а не мгновенно перекрашивается.
- **Модалки и поповеры**: появление fade+scale/slide 200–300мс, закрытие
  быстрее появления. Мгновенный display:block — грубо.
- **Списки и данные**: новые элементы появляются с коротким entrance
  (fade/translate 8–16px), изменения чисел — flash-подсветкой.
- Всё на transform/opacity, без layout-thrash; `prefers-reduced-motion`
  отключает всё перечисленное.

## «Старый сайт» — анти-паттерны

Признаки, по которым интерфейс выглядит десятилетней давности — проверяй
шапку и формы отдельно:

- Шапка-полоска: логотип-текст + ряд текстовых ссылок + прямоугольная кнопка
  без отступов-воздуха. Современная шапка: чёткая высота, blur/полупрозрачность
  при скролле (для скроллящихся страниц), иконки+текст, аккуратный user-menu.
- Формы «как в 2012»: узкие инпуты, label над полем мелким серым, кнопка
  «Отправить». Современная форма: поля ≥44px высотой, фокус-кольцо акцентом,
  иконки в полях по смыслу (глаз у пароля), сабмит на всю ширину.
- Auth-модалка: сухая карточка с двумя полями. Современный паттерн: визуальный
  блок (арт/бренд-панель) + форма, переключение вход/регистрация с анимацией,
  соц-вход или явное «демо, без соцсетей».
- Скругления вслепую: либо системный радиус из токенов, либо ноль — но не
  «3px потому что border-radius надо поставить».

## Типографика и tokens

- Заголовки могут быть выразительными, body-текст — спокойным и читаемым.
- Body не мельче 14px и с комфортным line-height 1.4–1.6.
- Никаких больше двух font-family.
- В Next.js подключай шрифты через `next/font`, а в CSS связывай их с
  `font-sans`, `font-serif` или `font-mono`.
- Определи design tokens для background, foreground, muted, border, primary,
  accent и radius. Компоненты должны использовать токены.
- Пары шрифтов по типу продукта: SaaS/dashboard — Geist или Inter; дружелюбный
  продукт — Manrope; мягкий чистый UI — DM Sans; editorial/premium — акцентный
  Fraunces или Playfair Display поверх нейтрального sans. Один основной +
  максимум один акцентный. Шкала размеров и line-height настраиваются системно,
  а не «увеличил текст вручную». Числа в интерфейсах с данными — моноширинный.

## Продуктовый реализм

«Настоящесть» интерфейса — не декор, а структура и живые данные:
- Реальная информационная архитектура домена: у биржи — order book, сделки,
  баланс, позиции; у магазина — корзина, заказы, статусы. Не одна красивая
  секция, а полный набор экранов/состояний продукта.
- Живые данные: значения меняются (flash-up/flash-down), есть ticker/marquee,
  пустые/loading/error состояния у всего, что грузится.
- Микроанимации дешёвые (transform/opacity/background-color), а не ререндер.
- Декоративный макет без продуктовой структуры = макет, а не продукт.

## Темы, контент, локали

- Светлая и тёмная тема строятся на одних токенах. Каждую правку проверяй в обеих (visual-gate снимает обе).
- Реальный контент, а не «Lorem»: длинные имена, 3-строчные заголовки, пустые списки,
  числа 1 и 1 000 000. Вёрстка обязана пережить строку x2 длиннее (немецкий/русский).
- Есть i18n: никаких строк в JSX мимо словаря; даты и числа через `Intl`. Для RTL используй
  logical properties (`ms-*`, `pe-*`, `start-*`), а не `ml-*`/`right-*`.
- `prefers-reduced-motion`, `prefers-color-scheme`, `forced-colors` — часть дизайна, а не опция.

## Дизайн-источник

- **Figma MCP** (`figma`, Dev Mode): `get_design_context` / `get_code` по выделенному фрейму,
  `get_variable_defs` для токенов, `get_screenshot` как эталон. Сопоставь переменные Figma
  с токенами из design-map. Не плоди параллельную палитру.
- Скриншот/референс сайта: открой его в Playwright, сними snapshot и screenshot, вытащи
  сетку, ритм и типографику. По памяти не воспроизводи.

## Компоненты

- Сначала переиспользуемые primitives: Button, Input, Badge, Card, Dialog,
  navigation и Section. Не делай огромный page-файл.
- Если проект использует shadcn/ui — пользуйся существующими компонентами и
  вариантами, не плодя почти одинаковые кнопки.
- Сложные блоки разделяй на компоненты с понятными именами.
- Не добавляй анимацию ради анимации. Один осмысленный entrance/transition лучше
  десятка прыгающих элементов. Учитывай `prefers-reduced-motion`.

## Инструменты и источники

Используй то, что реально есть в текущем агенте (поиск, браузер, MCP). Нет инструмента —
не делай вид, что пользовался им.

- SearXNG: найти свежие визуальные референсы и документацию.
- Playwright: открыть сайт, снять screenshot, проверить DOM, интерактивность и
  responsive-состояния. Это обязательная проверка для заметного UI.
- Fetch: прочитать конкретную страницу или документацию без браузера.
- Figma/Paper: если пользователь дал дизайн, сначала изучи его структуру,
  токены и размеры, потом реализуй.
- shadcn: добавлять только нужные primitives, не тащить весь каталог.

## Браузерная проверка

После каждого заметного UI-изменения проверь:

- нет ли пустого экрана, overflow и наложений;
- hero и CTA видны без прокрутки на desktop;
- мобильная навигация и кнопки не ломаются;
- focus-visible заметен;
- формы показывают понятные ошибки;
- скриншот выглядит цельно, а не как набор независимых карточек.

Машинные gates поверх глаз (контур ставит `frontend-init.mjs`): `e2e`, `a11y`
(скилл `a11y-audit`), `visual` (`visual-regression`), `perf` (`web-perf`).
Нет скрипта — gate `unverified`, а не «пропущено».
Нет Playwright/браузера у агента (бывает в desktop-приложениях) — запусти dev-сервер,
сними скриншоты через `npx playwright screenshot <url> shot.png` (desktop 1440 и mobile 390),
открой их как изображения. Не смог — честно напиши «визуально не проверено».

В финальном ответе кратко укажи, что реально проверил. Не заявляй «готово» только
на основании компиляции.

## Анти-слоп аудит (обязательный последний шаг)

Нейрослоп — это когда страницу можно поменять на любую другую AI-страницу и никто
не заметит. Перед «готово» пройди список по скриншоту и исправь каждое «да».

Клише, которые выдают AI (запрещены, если пользователь сам их не попросил):
- фиолетово-синие градиенты, градиентный текст в hero, glow-шары и blur-пятна на фоне;
- кремовый фон + serif-заголовок + терракотовый акцент «по умолчанию»;
- чёрный фон + один кислотно-зелёный акцент;
- hero «огромная цифра + мелкая подпись», ряд из трёх одинаковых stat-карточек;
- сетка 3×N одинаковых карточек «иконка + заголовок + 2 строки текста»;
- карточки с цветной полоской слева, `rounded-2xl shadow-lg` на всём подряд;
- нумерация 01/02/03 на том, что не является последовательностью;
- эмодзи вместо иконок, иконка над каждым абзацем;
- тексты-пустышки: «Unlock the power», «Seamless», «Revolutionize», «Elevate»,
  «Ваш надёжный партнёр», «Инновационные решения»; три одинаковых по длине пункта;
- выдуманные логотипы клиентов, отзывы, рейтинги «4.9/5» и цифры «10 000+ пользователей»;
- случайные анимации появления на каждом блоке, бегущие счётчики;
- «мёртвый» интерфейс: кнопки без active/hover-отклика, табы без transition,
  модалки, возникающие мгновенно (см. «Микровзаимодействия»);
- шапка и формы «как в 2012» (см. «Старый сайт — анти-паттерны»);
- навигация с мёртвыми пунктами (href="#", aria-disabled) — недоделанный
  продукт, см. full-site-checklist.

Проверь, что у страницы есть характер:
- палитра и шрифт выведены из самого продукта (его материал, среда, жаргон), а не из шаблона;
- есть ОДИН запоминающийся приём, остальное тихое; убери один чисто декоративный элемент;
- ритм отступов разный: плотные и воздушные секции чередуются, не всё `py-24`;
- заголовки конкретные: что именно, для кого, какой результат; кнопка = глагол + объект;
- закрой логотип — понятно ли, чей это сайт? Если нет, направление слабое, переделай.

В ответе перечисли, какие клише нашёл и что исправил.

## Анти-паттерны

- Не переписывай весь проект ради новой библиотеки.
- Не добавляй аналитику, backend или auth, если UI-задача этого не требует.
- Не хардкодь секреты и не вставляй их в URL, логи или skill-файлы.
- Не выдумывай референсы: если источник не открылся, скажи это и используй другой.
- Сначала исправляй самый заметный визуальный дефект, а не полируй мелочи.

## Применение

Если запрос не задаёт стиль, предложи короткое визуальное направление сам и сразу
реализуй его. Если есть референс, следуй ему по структуре, но не копируй чужую
айдентику без необходимости.

При конфликте между этим скиллом и явным запросом пользователя приоритет у запроса.
Безопасность, доступность и реальные данные не жертвуются ради красоты.
