# Project onboarding

Цель — файл, который следующей сессии за минуту даёт то, что сеньор знает о проекте.
Только факты, найденные в репозитории. Чего не нашёл — пиши «не найдено», не додумывай.

## 1. Разведка (read-only)

Ничего не меняй и не устанавливай на этом шаге.
- Манифесты: `package.json`, lock-файл (→ package manager), `pyproject.toml`, `go.mod`,
  `Cargo.toml`, `Dockerfile`, `docker-compose*`, `Makefile`, `.github/workflows/`.
- Конфиги: `tsconfig`, `next.config`/`vite.config`, линтер, форматтер, тестовый раннер,
  ORM/миграции, `.env.example` (только имена переменных, значения не читать и не копировать).
- Структура: `git ls-files | head -300`, крупные директории, точки входа.
- История: `git log --oneline -20`, активные ветки — чтобы понять, что сейчас меняется.
- Существующие правила: `README`, `CONTRIBUTING`, `CLAUDE.md`, `.cursor/rules`, `docs/`.

## 2. Проверь команды

Запусти read-only/безопасные проверки, чтобы записать **работающие** команды:
typecheck, lint, test (можно ограничить быстрым подмножеством), build — если это дёшево.
Каждую отметь: работает / падает (с первой строкой ошибки) / не запускал.
Установку зависимостей — только если без неё ничего не проверить, и сообщи об этом.

## 3. Напиши `AGENTS.md` в корне проекта

Коротко: 40–100 строк. Если файл уже есть — дополни недостающее, не переписывай чужое.

```md
# <Проект> — одной строкой что это и для кого

## Стек
Язык/рантайм + версия, фреймворк, БД/ORM, стили, тесты, деплой.

## Команды
- install: `...`
- dev: `...`
- typecheck / lint / test / build: `...`  (отметка, если сейчас падает)

## Структура
- `src/app/` — ...  (только значимые директории, 5–12 пунктов)

## Соглашения
Как сделаны роуты, доступ к данным, валидация, ошибки, компоненты, стили, именование.
Ссылка на эталонный файл для каждого: «новый эндпоинт — как `src/api/users.ts`».

## Не трогать / осторожно
Сгенерированные файлы, миграции на проде, публичные API, секреты, легаси-зоны.

## Известные проблемы
Падающие проверки, флаки, TODO с риском — по факту из шага 2.
```

## Правила

- Никаких секретов, токенов, значений из `.env`, внутренних URL с ключами.
- Не дублируй общий харнесс (стиль общения, память) — только специфика проекта.
- Утверждение без источника в репозитории — не пиши.
- Создание файла в проекте — обычное изменение; коммит — только по просьбе.

## 4. Junction скиллов для Freebuff (Windows)

Freebuff читает скиллы только из проектной папки `<проект>/.agents/skills`. Чтобы
он видел глобальный набор харнесса, создай junction (если его ещё нет):

```
mkdir .agents
cmd /c mklink /J .agents\skills %USERPROFILE%\.agents\skills
```

Уже есть `.agents/skills` (junction или папка) — не трогай, отметь в ответе.

## Ответ

Краткий итог: стек одной строкой, какие команды работают/падают, 3 главных риска
проекта, путь к созданному `AGENTS.md`. Предложи 1–2 следующих шага по делу.
