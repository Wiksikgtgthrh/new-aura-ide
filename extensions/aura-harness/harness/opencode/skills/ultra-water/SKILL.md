# Ultra-Water

Движок воды и окружения: берём как есть, а не переписываем.

## Вода — главный объект, а не фон-пейзаж

Когда просят «реалистичную воду» для сайта или приложения, в кадре должна быть
**только вода**. Остров, постройки, деревья и плавучие обломки — это чужие
главные роли: они отбирают внимание у того, ради чего всё делалось.

Для сайта это значит: **камера на воду, остров и обломки выключены по
умолчанию** (движок ставит их сам — гаси в своём слое), вода занимает почти
весь экран. Остров включай, только если он несёт геймплей; тогда все высоты
бери из `world.heightAt(x, z)`, иначе объекты повиснут или утонут.

- Гаси лишнее прямо в сцене: `terrain.group.visible = false`,
  `floaters.scene.visible = false` (поля приватные — обращайся через
  приведение типа, но не правь `src/uw/`: движок остаётся как есть).
- Камера — низко и близко: высота 4–15 м, FOV 46–56°, цель чуть ниже камеры,
  чтобы горизонт стоял в верхней трети и поверхность занимала почти весь экран.
  С 100+ метров вода превращается в текстуру и «реалистичность» пропадает.
- Смотри наружу от острова, а не на него: маршрут камеры веди по азимуту вокруг
  центра мира, чтобы суша оставалась за спиной.
- Облака приглуши (`sky.params.cloudCoverage` ≈ 0.2): при низкой камере они
  съедают полкадра.
- Тихая лагуна, а не шторм: `windSpeed` 5–7, `waveScale` 0.7–0.8,
  `swellScale` 0.45–0.55, `choppiness` 0.55–0.65. С заводскими 9 м/с вода
  выглядит северной и свинцовой, рябь бьёт по глазам.
- Цвет добивай на воде, а не на небе: `uAbsorption` ≈ (0.22, 0.04, 0.022),
  `uScatterColor` ≈ (0, 0.14, 0.20) — иначе океан серо-стальной вместо бирюзы.
- Под текст оставляй «тихую» половину кадра: цель смещай вбок, а не по центру.

## Проверка «стек-совпадения» — первым делом

Прежде чем писать шейдеры самому, измерь референс:

```bash
git clone --depth 1 <repo> /tmp/ref && du -sh /tmp/ref && find /tmp/ref -type f | wc -l
grep -rn "^import" /tmp/ref/src | sort -u          # на чём он вообще написан
grep -n "\"three\"" /tmp/ref/package.json           # версия three
cat /tmp/ref/LICENSE /tmp/ref/THIRD_PARTY_NOTICES.md
```

Дальше два исхода:

* **Стек совпал** (тот же three.js, MIT, код читаемый и небольшой) → **берём
  движок целиком**, лицензию сохраняем. Ultra-Water — ровно этот случай:
  31 файл, ~4 500 строк, ноль бинарных ассетов, three r186.
* **Стек другой** → берём приём по правилам `swipe-file`: минимальный модуль
  или шейдер, переписанный под проект.

Ошибка, которую тут легко сделать: решить по описанию, что это «тяжёлый чужой
движок», и пойти писать своё. Сначала измерь — README преувеличивает.

## Установка одной командой

```bash
node ~/.agent-harness/tools/water.mjs ~/Projects/<проект>          # поставить
node ~/.agent-harness/tools/water.mjs ~/Projects/<проект> --dry    # что будет сделано
```

Инструмент идемпотентен, без `--force` не перезаписывает ничего. Он:

1. кладёт эталонный движок в `src/uw/` вместе с `LICENSE` и
   `THIRD_PARTY_NOTICES.md` (их удалять нельзя — внутри credit'ы three.js AgX,
   хеша Хоскинса и атмосферы Хиллера);
2. кладёт интеграционный слой `src/world/world.ts` и страницу проверки
   `uw-check.html` + `src/uwcheck.ts`;
3. правит `package.json` (three → r186), `tsconfig.json` (`allowJs: true`,
   `checkJs: false` — их JS тогда не проверяется, а типы выводятся),
   `vite.config` (алиас `three/addons` → `three/examples/jsm`).

Дальше: `npm install`, `npm run dev`, открыть `/uw-check.html`.

## Карантин

Сначала проверь движок **отдельной страницей**, и только потом подключай
геймплей: `/uw-check.html` показывает небо, остров, воду и подводный вид без
единой строки твоей логики. Так сразу видно, чей баг — движка или твоего слоя.

Ожидаемый признак жизни: в консоли пусто, `renderer.info.programs` ≈ 20+,
в кадре остров с прибоем. Он всё: движок поднялся.

## Подключение игрового слоя

`World` из `src/world/world.ts` — единственная точка входа. Он держит
`renderer`, `camera`, `scene` и один кадр.

* **Кадр отдан движку.** `world.render(dt)` сам проходит отражение → непрозрачное
  в HDR → вода в тот же MSAA → подводный проход → постобработка. Свой
  `renderer.render()` больше не вызывать: рендерер создаётся с
  `antialias: false, depth: false, autoClear = false`, и порядок кадров —
  часть конвейера.
* **Камера — твоя.** `world.camera` ведёт твой контроллер. Не трогай её
  `near/far` без нужды: подводный проход восстанавливает лучи по проекции.
* **Рельеф — `world.heightAt(x, z)`** (это `islandHeight`). Любая игровая
  постановка — враги, деревья, спавн — идёт через него, иначе объекты повиснут
  в воздухе или утонут.
* **Вода — `world.camWater`** (высота поверхности под камерой) и
  `world.submerged` (камера под водой). Читаются из GPU с задержкой 1–3 кадра —
  для буйности и кислорода этого достаточно.
* **Отражение — слой 1.** Всё, что должно блестеть в воде, регистрируй через
  `world.register(root)`: он включает слой 1 каждому потомку (в three слой
  проверяется по объекту, не по поддереву). `World` перепроходит
  зарегистрированные корни каждый кадр, поэтому динамические снаряды и эффекты
  подхватываются сами.
* **Солнце — `world.setSun(elevation, azimuth)`**, не чаще, чем меняется время
  суток: пересчёт перепекает кубическую карту неба.

## Грабли (все проверены на практике)

* **three ≥ r186.** Нужны MRT (`WebGLRenderTarget({count: 2})`),
  `readRenderTargetPixelsAsync` и `DepthTexture` в HDR-таргете.
* **`three/addons`** в их модулях (`BufferGeometryUtils`) — без алиаса Vite не
  соберётся.
* **`WaterQuery` асинхронна и молчалива.** При `inFlight >= 2` новые запросы
  отбрасываются, ошибки readback глотаются. Не зови её чаще одного раза за кадр
  и не жди мгновенного результата.
* **Тени статичны:** `shadowMap.autoUpdate = false`, пересчёт по `needsUpdate`
  (движок включает его при смене солнца). Динамические актёры либо получают
  свою карту, либо не бросают тень — реши осознанно.
* **Телефон и слабое железо — не тот же профиль.** Держи тиры качества
  (`?q=high|medium|low|min`): на `min` разрешение 0.4, без MSAA и отражений.
* **Софтверный рендер этот конвейер в реальном времени не тянет** (десятые доли
  кадра в секунду). Логику проверяй прогоном `update(dt)` в цикле **без**
  отрисовки, а картинку — статичными кадрами. Не делай вывод о плавности по
  софтверному скриншоту.
* **Не тащи их `main.js`.** Он демо-каркас: `OrbitControls`, `lil-gui`, пресеты
  камер, GUI плавучих обломков. Для игры из них нужен только порядок кадров,
  уже перенесённый в `world.ts`.
* **Атрибуция обязательна:** MIT. `src/uw/LICENSE` и
  `src/uw/THIRD_PARTY_NOTICES.md` остаются в репозитории, ссылка — в docs.
