# Observability & Incident Response

## После деплоя (10–15 минут)

- Health: `curl -s -o /dev/null -w "%{http_code} %{time_total}\n" https://<host>/health` каждые 1–2 минуты.
- Доля 5xx и p95 латентности против значений до релиза.
- Новые типы ошибок в логах. Рост больше чем в 2 раза значит откат по rollback.md.

## Диагностика VPS (сначала только чтение)

```bash
ssh <alias> 'uptime; free -h; df -h; ss -tlnp | head -20'
ssh <alias> 'systemctl --failed; systemctl status <service> --no-pager -n 30'
ssh <alias> 'journalctl -u <service> --since "30 min ago" --no-pager | tail -100'
ssh <alias> 'docker ps --format "{{.Names}} {{.Status}}"; docker logs --tail 100 <container>'
```

`ssh` в политике `ask`, каждую команду подтверждает человек. Порядок гипотез: диск → память/OOM → упавший сервис → сеть/порты → внешняя зависимость → код.

## Логи приложения

- Структурированные (JSON): время, уровень, request id, маршрут, длительность.
- Секреты, токены и персональные данные в лог не попадают.
- На каждую ошибку контекст: что делали, с какими параметрами (замаскированными).

## Инцидент: отчёт

```
Что сломалось: <симптом для пользователя>
Когда: <начало / обнаружение / восстановление>
Причина: <факт> · Гипотезы: <если не доказано>
Что сделали: <шаги с временем>
Что поменять, чтобы не повторилось: <1–3 пункта>
```
