# Testing

Тест нужен, чтобы поймать регрессию. Тест, который не может упасть, хуже отсутствия
теста: он даёт ложную уверенность.

## Шаг 0. Как тестирует проект

- Найди раннер и команды: `package.json` scripts, `vitest.config`, `jest.config`,
  `playwright.config`, `pytest.ini`, `go test`. Используй их, не вводи второй фреймворк.
- Посмотри 2–3 существующих теста рядом с кодом и повтори их стиль, фикстуры, хелперы.
- Нет тестов вообще — предложи минимальный раннер под стек, поставь после согласия.

## Что покрывать

По убыванию ценности:
1. **Баг, который только что исправили** — тест обязателен, и он должен падать без фикса.
2. Бизнес-правила и расчёты: деньги, права доступа, статусы, даты, лимиты.
3. Границы: пусто, null, 0, отрицательное, максимум, unicode, часовые пояса, дубли.
4. Пути ошибок: невалидный ввод, недоступный сервис, таймаут, нет прав.
5. Контракты между модулями и API (форма ответа, коды статусов).

Не покрывай: геттеры, реэкспорты, код фреймворка, разметку ради процента покрытия.

## Уровень

- **Unit** — чистая логика без I/O. Быстро, много.
- **Integration** — модуль с реальной БД/файлами/HTTP-слоем (тестовая БД, контейнер,
  in-memory аналог). Здесь ловится большинство реальных багов.
- **E2E** (Playwright) — только критические сценарии пользователя: вход, оплата,
  основная форма. Мало, но обязательно для них.

## Как писать

- Один тест — одно поведение. Имя описывает поведение: `rejects expired token`, а не `test2`.
- Arrange → Act → Assert. Проверяй результат и наблюдаемые эффекты, а не внутренние вызовы.
- Детерминизм: фиксированное время (fake timers), сиды, без зависимости от порядка и сети.
- Моки — только на границе системы (внешний API, почта, оплата, время). Не мокай свой же
  модуль, который тестируешь, и не мокай БД там, где можно поднять тестовую.
- E2E-селекторы — по роли и тексту (`getByRole`), не по CSS-классам.
- Ожидания — по состоянию (`await expect(...).toBeVisible()`), не `sleep`.

## Проверка, что тест настоящий

Для нового теста на баг или правило: временно сломай код (или откати фикс) и убедись,
что тест **падает с понятным сообщением**. Не упал — тест бесполезен, перепиши.

## Запрещено

- Менять ожидание в тесте под текущий (неверный) результат кода.
- `skip`/`only`/удаление падающего теста без объяснения пользователю.
- Снапшоты огромных объектов вместо явных проверок важных полей.
- Тесты, зависящие от реального внешнего API, текущей даты или порядка запуска.

## Ответ

Какие тесты добавлены/изменены и что каждый ловит; команда запуска и её результат;
подтверждение, что новый тест падает без фикса; что осталось без покрытия.
