# Three.js стек

3D — самый простой способ убить и перф, и сроки. Правило: сначала сцена живёт и
вертится, потом красота. Никогда не наоборот.

## Выбор подхода

- **React-проект (Next/Vite + React)** → React Three Fiber + `@react-three/drei`.
  Не мешай vanilla Three в React-компоненты через useRef — ад с lifecycle.
- **Ванилла/лендинг без React** → чистый Three.js, один модуль `scene.ts`,
  экспортируй `init(canvas)` и `dispose()`.
- Версию API сверяй через `docs-lookup` — Three ломает совместимость между
  релизами (r150+ — другой color management, r160+ — другие примеры импорта).

## Минимальная живая сцена (чек-лист «чёрный экран»)

Если экран чёрный — иди по списку, 95% случаев здесь:
1. Canvas имеет размеры? (нулевая высота контейнера — классика)
2. Камера смотрит на объект? (`camera.position.z > 0`, `lookAt`)
3. Есть свет? (MeshStandardMaterial без света = чёрный)
4. Рендерер создан с правильным canvas и размером, `setPixelRatio` учтён
5. Цикл `requestAnimationFrame` запущен / `<Canvas>` смонтирован
6. Цвет фона не совпадает с цветом объекта

## Производительность — не опция

- `setPixelRatio(Math.min(devicePixelRatio, 2))` — больше двух не надо никому.
- Геометрию/текстуры переиспользуй, не создавай в кадре. В кадре — только мутации.
- Текстуры: KTX2/basis если серьёзно, иначе WebP; размеры степенью двойки.
- `frustumCulled`, instancing для повторов (`InstancedMesh`), draco/meshopt для
  тяжёлых GLTF.
- На слабом железе и в фоне — рендер по требованию (`frameloop="demand"` в R3F).
- Вкладка не видна → цикл спит. `document.visibilitychange` — обязательно.

## Память и unmount

Утечки GPU — главный баг долгоживущих страниц. При размонтировании:
`geometry.dispose()`, `material.dispose()`, `texture.dispose()`,
`renderer.dispose()`, снять rAF. В R3F это почти бесплатно, в ванилле — твоя
забота. SPA-навигация туда-сюда 10 раз не должна расти по VRAM.

## Модели и ассеты

- GLTF/GLB — стандарт. `GLTFLoader` (ванилла) / `useGLTF` (R3F) + `DRACOLoader`
  при сжатии.
- Модель > 5 МБ — сожми (`gltf-transform optimize`) до того, как пихать в public.
- Пока грузится — скелет/прогресс (`useProgress` в drei), а не пустой экран.


## «Живость» растений/ткани: ветер и параллакс

- Покачивание — синусоида по rotation/position, но **с разными фазой и
  амплитудой у частей** объекта: стебель медленно и сильно, листья быстрее и
  слабее. Один синус на всё = механическое дёрганье.
- В `useFrame`/rAF: углы накапливай из времени, не мутируй стейт React на кадр.
- Параллакс к курсору: камера плавно следует (lerp к цели, factor ~0.05),
  амплитуда 2–5% — ощущение объёма без морской болезни.
- Глубина: мягкий ключевой свет + fill, тени, лёгкий DOF/blur фона.
- Готовая GLB/GLTF-модель почти всегда лучше процедурной геометрии: бери
  модель, анимируй кости/вершины ветром.

## Физика (Rapier)

- 2D/3D физика в браузере → **Rapier** (`@dimforge/rapier3d-compat` / `2d-compat`),
  в R3F — обёртка `@react-three/rapier`.
- Физический мир шагается фиксированным шагом (fixed timestep), рендер —
  по rAF; не привязывай step к кадру 1:1.
- Тела/коллайдеры создавай один раз, в кадре — только impulses/positions.
- Сотни тел — смотри на `instanced` rigid bodies; тысячи — пересмотри идею.

## Постпроцессинг и шейдеры

- R3F: `@react-three/postprocessing`. Ванилла: `EffectComposer`.
- Bloom + SSAO на полный экран — дорого. Сначала замерь fps, потом включай.
- Свои шейдеры — `ShaderMaterial`; uniforms наружу, не пересоздавай программу.

## Доступность и запасной путь

- 3D не должно быть единственным носителем смысла: контент дублируется текстом.
- `prefers-reduced-motion` → статичный кадр или отключённая анимация.
- Нет WebGL → заглушка-картинка, а не белый экран.

## Готовые движки вместо самоделок

Два проверенных переноса из открытых репозиториев (оба MIT, оба ставятся одной
командой из харнесса) — сначала они, и только потом свой шейдер:

- **океан, небо, остров, подводный вид** → скилл `ultra-water`, инструмент
  `node ~/.agent-harness/tools/water.mjs <проект>`;
- **боевые эффекты и заклинания** (39 штук, 10 стихий: портал, метеорит,
  заморозка, цунами, вихри, щиты) → скилл `ultra-elements`, инструмент
  `node ~/.agent-harness/tools/spells.mjs <проект>`;
- **пиксельные спрайты и эффекты** (244 штуки кодом, без картинок) → скилл
  `pixelfx`; в three.js композит кадра загружается текстурой, для других
  движков — экспорт спрайт-листа.

Оба — three.js + Vite, вендорятся целиком вместе с лицензиями; интеграционные
грабли и адаптеры к своему миру описаны в соответствующих скиллах.

## Проверка перед сдачей

- 60 fps (или честные 30) на среднем ноуте, без просадок при скролле.
- Chrome DevTools → Performance/Memory: нет роста VRAM при навигации.
- Скриншоты desktop/mobile — 3D на 375px тоже обязано работать.
