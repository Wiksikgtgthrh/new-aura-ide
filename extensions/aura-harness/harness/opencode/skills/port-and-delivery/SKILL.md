# Порт под другую ОС и доставка изменений

Два воркфлоу, которые обычно идут рука об руку: сперва переносишь проект на
другую ОС, потом везёшь изменения туда, где нет прямого доступа к репозиторию.
Детали и грабли — в `references/`.

## Куда что

| Трек | Когда | Референс |
|---|---|---|
| **Порт под другую ОС** | перенести linux-проект на Windows, не сломав Linux | [`references/windows-port.md`](references/windows-port.md) |
| **Доставка изменений** | принять чужие наработки файлами и влить через PR/merge | [`references/pr-from-files.md`](references/pr-from-files.md) |

## Сквозные принципы

- **Живая верифа, тестов нет.** Каждый кусок — запустил, увидел, показал.
- **Ядро не трогаем.** ОС-специфику прячем за фасад, ядро о платформе не знает.
- **Платформенный интерфейс обязателен для всех адаптеров.** Если ядро зовёт
  метод платформы — его обязан реализовать каждый адаптер, пусть даже пустышкой
  (no-op). Иначе «расширение под другую ОС» ломает текущую.
- **`merge-base` — прежде чем мержить.** «Полная история» ≠ «поверх main»;
  иначе merge молча откатит твои правки.
- **После мержа:** новые зависимости → `npm install`; нативные модули → ленивый
  импорт только под свою ОС (`await import` под `win32`/`linux`); если крутится
  сервис — перезапустить и проверить.
- **Чужую ОС здесь не проверить** → PR как гейт + тест на целевой машине.

## Быстрый чек-лист

**Порт:** разведка окружения → platform-слой (`posix`/`win`) → живая верифа
(нативка, движок, сервер, запись) → лаунчер + универсальный загрузчик модели + README.

**Доставка:** `bundle verify`/`list-heads` → `fetch` во временный ref →
`merge-base` → diff + живая верифа → `push` ветки → `gh pr create` →
`gh pr merge --merge --delete-branch` → `pull`/`prune`.

## Базовые команды

```bash
# принять bundle
git bundle verify x.bundle && git bundle list-heads x.bundle
git fetch x.bundle refs/heads/<br>:refs/heads/<tmp>
git merge-base main <tmp> && git log --oneline main..<tmp>

# влить через PR
git push origin refs/heads/<tmp>:refs/heads/feat/<name>
gh pr create --base main --head feat/<name>
gh pr view <N> --json mergeable,state
gh pr merge <N> --merge --delete-branch
```

Полные шаги и грабли — в референсах выше.
