# Game Dev — браузерные игры

## Выбор стека по типу игры

- **2D игра** → Phaser: сцены, спрайты, физика, тайлы, звук, ввод из коробки.
- **Мини-игра/прототип** → Canvas 2D + TypeScript: полный контроль, ноль
  зависимостей.
- **3D** → Three.js / React Three Fiber (см. threejs-stack): сцена, камера,
  свет, GLB-модели, частицы, постэффекты.
- **Большой проект** (уровни, редактор, много контента) → Godot/Unity с
  экспортом в WebGL. Не пиши это на Canvas руками.
- **Мультиплеер** → WebSocket/Colyseus, **server-authoritative**: важная
  логика (урон, деньги, победа) никогда не доверяется клиенту.

## Главное архитектурное правило

React НЕ перерисовывает кадры. React — только UI поверх игры: меню, магазин,
профиль, лобби, настройки, авторизация. Игровой цикл живёт отдельно
(Phaser-сцена / canvas / R3F canvas) и общается с UI через события/стор.

## Игровой цикл и перф

- `requestAnimationFrame` для рендера, **фиксированный timestep** для физики
  и логики (аккумулятор времени), чтобы поведение не зависело от fps.
- Ассеты грузятся заранее (preload), спрайты — в атласы, не россыпью png.
- Повторяющиеся объекты (пули, частицы, враги) — **object pool**, а не
  new/delete каждый кадр.
- Тяжёлые вычисления (поиск пути, генерация) — в Web Worker.
- Анимации движка — только transform/opacity на уровне композитора, где можно.

## Сочность (game feel)

То, что отличает «работает» от «играется»:
- bloom, particles, parallax-фоны, screen shake при ударах;
- плавные transitions между состояниями, а не мгновенные смены;
- отклик на ввод мгновенный: звук/анимация в кадр нажатия;
- управление: мышь + клавиатура + touch, responsive.

## Проверка

- Стабильный fps на среднем железе (DevTools Performance, CPU throttle).
- Память не растёт при длинной сессии (pool'ы работают, dispose вызывается).
- Мобильный тач проверен на реальном вьюпорте 390px.
